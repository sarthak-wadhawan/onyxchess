Game loop

All the individual components are ready. We now need to connect them into a program that responds to a person, applies the rules and knows when to stop. The game loop in main.cpp coordinates the modules without duplicating their logic.

Decide whose turn it is

Initialize the board once. At the beginning of every iteration, display the current position and generate its legal moves. If none exist, check whether the current king is attacked. Report checkmate or stalemate and exit the loop. Otherwise, branch according to the active color.

Accept and validate the player's move

White is controlled by the human in the supplied program. The user enters a source and destination such as e2e4. For promotion, an additional character specifies the desired piece.

  1. Read the input and stop if the user requests to quit or the input stream closes.
  2. Check the input length and convert the source and destination into square indices.
  3. Search the existing legal move list for the requested action, including the promotion choice when required.
  4. If no match exists, explain that the move is invalid and return to the same turn without changing the board.
  5. If there is a match, pass the validated Move record to make_move.

Matching against the generated list is safer than reconstructing special flags from raw user input.

Let the computer respond

On Black's turn, call find_best_move with the configured depth. The native teaching engine uses depth four. Record how long the search took, display the move, score and node count, and apply the selected move. The board executor switches the active side automatically.

The demonstration here lets you play both sides manually, so you can observe the state transitions independently of the search. Move a white pawn, then a black pawn. White becomes active again. Undo or reset to repeat the experiment.

Know when to stop

Only the side whose turn it is can be declared checkmated or stalemated. A player temporarily unable to move immediately after making their own move does not end the game. The next loop iteration checks the new active side.

The native teaching program handles checkmate and stalemate. Repetition and other draw rules need additional history or state; the browser game uses its own rules implementation for these. Do not assume the two implementations are identical.

Test the complete loop

Try a valid opening move, an invalid move and a promotion. Invalid input must leave the position unchanged, valid input must change the turn, and promotion must preserve the chosen piece. The native program also accepts quit to end the session.
