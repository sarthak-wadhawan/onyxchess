Board logic

Now that we have a representation, we need operations that read and update it. The board module owns these operations; it does not decide which move is best.

Initialize the board

The initialize_board function creates a consistent starting state. Fill the first rank with White's major pieces, the second with pawns, ranks three through six with empty squares, and the last two ranks with Black's pieces. Queens begin on d1 and d8.

Next, set White to move, enable all four castling rights, clear the en passant target and initialize the clocks to zero and one respectively. Copy exactly 64 entries into the board.

The print_board function reads that same array in reverse rank order, from rank eight down to rank one. This displays White at the bottom without changing how the board is stored.

Convert coordinates and locate the king

The player sees e2, while the engine sees index 12. The sq_to_algebraic helper converts an index into its file letter and rank digit. Its reverse, algebaraic_to_sq (the spelling in the project), validates the two characters and reconstructs the index; invalid coordinates return -1.

The find_king function chooses the piece code for the requested color and scans all 64 squares until it finds that king. It returns the square index or -1 if absent. Full game positions require both kings; isolated teaching diagrams need not have them.

Is a square under attack?

The is_sq_attacked function answers a question about one square and one attacking color. Start at the square being tested and work outward:

  1. Check the eight knight offsets for a knight of the attacking color.
  2. Look back along the two possible pawn attack diagonals.
  3. Inspect the eight neighboring squares for the enemy king.
  4. Trace diagonal rays for bishops or queens, and straight rays for rooks or queens. Stop at the first occupied square on each ray.

Return true as soon as an attacker is found; otherwise return false. The board here shows the related idea of squares controlled by a bishop. A friendly pawn can be defended even when the bishop cannot move onto its square.

The is_in_check function combines find_king and is_sq_attacked: locate the king and ask if the opposing color attacks that square.

Apply a move

The make_move function receives an already validated action. Read the moving piece before clearing its original square. Put it at the destination, replacing a captured piece if necessary. Special flags determine whether to remove an en passant pawn, replace a promoted pawn or reposition a castling rook.

The visible move is only part of the update. Revoke castling permissions after the relevant king or rook moves or the rook is captured. Clear the old en passant target, creating a new one only after a two-square pawn move. Reset the half-move clock for pawn moves and captures; otherwise increment it. Finally, increment the full-move number after Black and switch the turn.

Check your logic

After e2–e4, the pawn should occupy e4, e2 should be empty, the temporary en passant target should be e3 and Black should be next. A move must update these together.
