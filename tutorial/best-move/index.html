Finding the best move

The recursive search tells us how valuable a position is. The actual game needs to know which action to take. The root function find_best_move connects those two responsibilities.

What should the function return?

The search_result structure contains the best move, its evaluation score and the number of nodes searched. Keeping these together makes the decision inspectable. The node count is a measure of search effort, not a measure of move quality.

Select an action at the root

The root position belongs to the player requesting a decision. It needs to compare legal moves rather than return only a number.

How find_best_move works

  1. Reset the node counter and generate the legal move list.
  2. If no moves exist, return a terminal score; there is no action to apply.
  3. Otherwise initialize the best move from the list and the best score to a very low value. Order the candidates and start a wide alpha-beta window.
  4. Copy the board for each candidate, apply that move and call Negamax at one less ply.
  5. Negate the opponent-relative result. If it exceeds the best score, remember the new score and move. Raise alpha as appropriate.
  6. Return the remembered move, score and total visited nodes.

Select depth one or two, then run the search. Compare which moves look promising before and after considering an opposing reply.

Interpret the scores

A positive score favors the side that requested the search; a negative score favors its opponent. Scores are in centipawns, not win probabilities. Mate scores are special terminal values.

The browser explorer searches each root candidate with a full window to display comparable independent values. The C++ engine shares alpha across candidates, so rejected candidates can return bounds. The browser and native engine may therefore count different numbers of nodes.
