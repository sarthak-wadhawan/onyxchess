Alpha-beta pruning

We know how to evaluate a tree, but many of its branches cannot change the final decision. Alpha-beta pruning recognizes these branches early, allowing the engine to search fewer positions while preserving the minimax result at the same depth.

When is a branch no longer useful?

Suppose MAX already has a branch that guarantees a score of 3. The next branch is controlled by MIN. As soon as MIN discovers a choice worth 2, that branch can return at most 2. There is no reason for MAX to choose it, even if its other leaves are worth much more.

Step through the tree. After branch A establishes 3, the first leaf of branch B establishes an upper bound of 2. The remaining leaves of B are skipped. Reverse the order and compare how much work is needed. The chosen value stays the same even when the number of examined leaves changes.

Keep two bounds

Alpha is the best lower bound MAX has established. Beta is the best upper bound MIN has established. A branch is no longer useful when the lower bound reaches or exceeds the upper bound. A cutoff is not a guess that a position looks bad; it follows from a bound already established by the search.

How the engine adds pruning to Negamax

  1. Start the root search with a very wide window, so no candidate is excluded prematurely.
  2. In each recursive call, generate legal moves and handle terminal positions and the depth limit as before.
  3. Search each child with the window reversed and negated because the player perspective changes.
  4. Negate the returned child score. If it reaches or exceeds beta, stop searching the remaining siblings and return beta.
  5. Otherwise, raise alpha if the score improves the best lower bound. Continue until all necessary children have been examined.
  6. Return alpha at the end of the search.

The engine uses a fail-hard cutoff, so an individual bounded subtree may return a bound rather than its exact independent score. The root decision remains correct under the standard minimax assumptions.

Check that pruning preserves the result

Set the first branch leaves to 10, 11 and 12. Compare the root value with the unpruned tree on the previous page. With the other leaves unchanged, both return 10. Count the leaves inspected rather than assuming pruning always saves the same amount of work.
