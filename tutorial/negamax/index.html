Minimax and Negamax

A good-looking move can be a trap. Capturing a piece may allow the opponent to capture something more valuable immediately afterward. Evaluating the current board alone cannot reveal that consequence. Search explores possible future decisions before choosing the next action.

Build a game tree

A tree represents positions as nodes and moves as branches between them. The root is the current position. Every legal move leads to a child position, where the opposing player can respond. A ply is one move by one side; four plies include two moves per player.

We cannot explore an entire chess game in practice. A depth limit tells the engine when to stop expanding a branch and estimate the remaining position using evaluation.

Minimax: assume the opponent responds well

Consider a two-player zero-sum game in which a larger score is better for MAX and worse for MIN. MAX chooses the largest available value; MIN chooses the smallest. A leaf is a position we evaluate without exploring further.

In this example the root has three choices. Branch A has leaf scores 3, 5 and 6, so MIN can force 3. Branch B has 2, 9 and 8, so MIN can force 2. Branch C has 4, 7 and 1, so MIN can force 1. MAX chooses A because 3 is the best guaranteed result. Run the trace and change one leaf to see how its score propagates upward.

Negamax: remove the duplicated logic

Minimax describes two different operations, maximizing and minimizing. In a zero-sum game, a score of +5 for one side means -5 for the other. Minimizing the opponent's score is therefore equivalent to maximizing our own score after reversing the sign.

This is why the engine needs only one recursive search function, negamax. Every call treats the side currently moving as the maximizing player. The child's score is expressed from the opponent's perspective; negate that score when it comes back to the parent.

How negamax works

  1. Generate the legal moves for the current position.
  2. If the list is empty, return a loss score for checkmate or zero for stalemate. Check this before applying the depth limit.
  3. If the remaining depth is zero, return the positional evaluation.
  4. Otherwise, for each legal move, copy the position and apply the move.
  5. Call the same search function on the resulting position with one less ply remaining. Negate the returned score.
  6. Retain the highest result and return it to the caller.

The base cases stop recursion. Copying each board prevents one branch from changing the state of another. The actual project also uses a mate-distance adjustment and alpha-beta bounds, which we introduce next.

Why search becomes expensive

If each position has roughly 20 legal moves, two plies produce about 400 leaf positions; four plies produce about 160,000. The real branching factor varies, but the growth explains why searching deeper becomes expensive. We need a way to avoid evaluating branches that cannot affect the decision.
